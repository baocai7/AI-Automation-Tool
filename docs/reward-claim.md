# 启动积分领取的每日记录

WorkBuddy 和 Qoder 分别保存已确认领取的北京时间日期，位于本项目 SQLite 数据库的 `reward_claim_daily` 表。
同一天再次启动时，在唤起客户端之前检查记录；已确认的客户端既不打开，也不执行关闭命令。
到下一个北京时间日期后，下一次启动投递助手可以重新领取。应用持续运行时不新增定时领取任务。

只有客户端确认成功才保存记录。未确认、失败、未启用均不伪装为已领取；某个平台失败不会阻止另一个平台领取。
成功后按现有 `reward-claim.close-after-confirmed` 设置单独关闭本次领取的客户端，已跳过的客户端不受影响。

升级时读取本项目 `target/logs/get-jobs.log` 中当天 RewardClaimService 的精确成功行，补入旧版本已确认记录。
不将旧日期、未确认日志或其他服务的输出当成成功。首次升级时，用户明确确认的 WorkBuddy 当日领取结果已保存。
数据库结构通过 `V20261018_02__reward_claim_daily.sql` 幂等新增；重复初始化不会覆盖记录。回退代码时保留此表即可。

可见日志示例：`WorkBuddy 今日已确认领取，跳过启动客户端`、`Qoder 今日已确认领取，跳过启动客户端`。
