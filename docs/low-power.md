# 本机低负载运行

日常启动：在项目根目录运行 `bash start-getjobs.sh`；需要后台运行时使用 `BG=1 bash start-getjobs.sh`。
需要验证并更新后端时运行 `bash restart-getjobs-verified.sh`。两个入口均直接运行打包好的 JAR，不再让 Gradle 随服务常驻。运行包按内容哈希保存在 `build/runtime/`，后续构建不会覆盖正在运行的文件；不自动删除旧副本。
日志追加到 `/tmp/getjobs.log`，标准轮转日志和自动回复事件数据库照常保留。

## 保留的功能和调度

- Boss 页面常驻，未读自动回复仍按原设置每分钟检查，发送确认、去重和回复统计不变。
- 猎聘、51job、智联在打开对应管理页时通过 POST `/api/playwright/platforms/{platform}/open` 初始化；投递服务也会确保对应页面已就绪。管理页暂时离开时不销毁用户正在使用的标签页。
- 扫码时每 3 秒检查登录；已登录后每 30 秒检查，导航事件仍能触发检查。
- 登录事件只注册一个共享监听器；管理页重连不会叠加监听器。51job 复用统一登录调度器，不再额外启动每秒轮询线程。
- 服务收到关闭信号后先停止各平台投递和自动回复；AI 返回期间若收到停止指令，取消发送，浏览器在专用线程关闭。
- AI 复用 HTTP 连接池，单次请求最多等待 60 秒；空闲业务线程允许回收。管理页隐藏后暂停健康轮询，重新可见时立即检查。
- 默认应用堆上限 512 MB、JVM 可用处理器数 2；Gradle 堆上限 1 GB、构建并行度 2；前端静态导出并行度 2。Chrome 等子进程内存不包含在 Java 堆上限里。

内存较重的统计任务若有需要，可使用 `GETJOBS_HEAP_MB=768 bash start-getjobs.sh`。
处理器限制可用 `GETJOBS_PROCESSORS=4` 覆盖；这些参数只影响本项目 JVM。

前端源码变更后需要重新构建静态管理页；单纯刷新旧页面无法更新 JS。前端依赖仅用于构建，日常运行不启动 Next 开发服务。
启动积分领取等现有功能保留，项目不会替用户关闭其他软件或修改系统电源设置。

## 验证

后端回归覆盖按需创建页面、重复打开不重复建页、关闭后重建、未知平台拒绝、登录检测节流、忙时不堆积后台任务，以及 SSE 重连不累积监听器；自动回复原有回归继续执行。
CPU/RSS 只能说明采样时的进程负载，不能等同于机身温度；首次构建、Chrome 启动、投递和 AI 请求期间会有短时负载。
